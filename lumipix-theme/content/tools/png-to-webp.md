## Lighter images for the web

PNG is great for screenshots, logos and graphics, but PNG files can be big, especially when a photo or a detailed illustration has been saved as PNG. Big images mean slower pages, more mobile data for your visitors and bigger uploads to your site. WebP was made for the web. It handles transparency just like PNG, and with a quality setting it usually produces much smaller files. All the main browsers show WebP these days, so it's a practical swap for PNG on most sites.

## Transparency stays transparent

WebP supports transparency, so the see-through parts of your PNG stay see-through. Logos, icons, cut-out products and stickers can go straight onto a coloured header, a card or a dark mode page without a white box around them. ## PNG vs WebP

| | PNG | WebP (from this tool) |
|---|---|---|
| Compression | Lossless | Lossy, set by **Quality** |
| Transparency | Yes | Yes |
| Typical file size | Bigger | Usually much smaller |
| Best for | Master copies, editing, pixel-exact graphics | Publishing on websites |
| Opens in | Pretty much everything | Current browsers and many apps |

The first row is the key one. PNG keeps every pixel exactly. The WebP you save here drops detail you're unlikely to notice in return for a smaller file, and the slider decides how much.

## Picking a quality

Different images react differently. Photos hide small losses well. Screenshots, text and hard edges show them sooner. Start here, then check the result and the size:

| Image type | Starting quality |
|---|---|
| Photos that were saved as PNG | 75 to 85 |
| Product cut-outs with transparency | 85 to 92 |
| Screenshots with small text | 90 to 95 |
| Logos, icons and line art | 92 to 100 |

If you can't see a difference between two settings, use the lower one. If text edges look fuzzy or flat colours get faint blotches, nudge it up and convert again.

## The pixel size matters too

Converting keeps the same dimensions. A 4000 pixel wide PNG becomes a 4000 pixel wide WebP, which is still far more than most page layouts need. For the biggest saving, shrink the image to the width it's actually shown at with the [image resizer](tool:image-resizer), then convert it here. ## If something's not right

**The WebP isn't much smaller.** Very small, simple graphics with few colours are already compact as PNG. Try a lower quality, or keep the PNG for those.

**Text or edges look soft.** Raise the quality and convert again from the original PNG.

**Colours look slightly different.** Colours are converted to sRGB, the standard for the web. Most images look the same, but files with an unusual colour profile may shift a little.

**An app won't open the WebP.** Some older software and upload forms still expect PNG or JPG. Keep the PNG for those, or [turn PNG to JPG](tool:png-to-jpg) when you don't need transparency.

**Only one frame was saved.** If you dropped an animated GIF or WebP, only the first frame is converted.

## When to keep PNG

WebP is better for publishing, but PNG still has its place. Keep PNG for files you'll edit again, graphics that must stay pixel-exact, and any platform or form that only accepts PNG. If you ever need to go back, you can [convert WebP to PNG](tool:webp-to-png) without losing transparency. For photos without transparency, a JPG may be fine too.
